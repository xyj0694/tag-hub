# 标签接单协作平台 — 产品需求文档（PRD）

> 版本：V1.0 | 状态：原型阶段（品牌方+平台方评审已完成） | 基于 2026-06-05 需求评审会议录音 | 原型评审 2026-06-07

---

## 一、项目背景与目标

### 1.1 项目背景

服装品牌方在向成衣工厂下达生产订单后，需要同步为每件服装配备对应的标签（吊牌标签、不干胶贴纸标签、洗麦标签）。标签虽小，却是服装生产的刚性配套辅料——没有标签，服装无法出厂销售。

当前行业痛点集中在三个方面：

1. **线下协作效率低**：品牌方通过邮件、微信向标签生产商发送 Excel 订单和图稿，人工传递容易出错，信息零散难以追溯。
2. **数据链路断层**：现有工具（如"骆驼系统"）仅具备商品档案和图稿传输功能，缺失订单状态跟踪、物流同步、对账回款等下游业务能力。EPC（电子标签唯一编码）、TID 等生产数据完全离线，前期数据无法监控。
3. **供应商管理粗放**：缺乏系统化保障，不敢引入小型标签生产商合作，导致产能弹性不足、议价空间受限。

### 1.2 平台定位

**标签接单协作平台** 是一个面向标签产业链的 B2B 业务协作系统，不是一个简单的数据传输工具。

平台串联三方角色，覆盖从下单到交付结算的完整业务流程：

- **品牌方**：提交标签订单、维护标签模板、跟踪生产进度、确认对账付款
- **平台方（运营团队）**：审核订单、拆分转单、协调供应商、处理异常
- **下游供应商（标签生产商）**：接单生产、上传 EPC 数据、发货、对账

### 1.3 核心价值

| 价值点 | 说明 |
|--------|------|
| **消除手工传递** | 品牌方在线下单，供应商在线接单，替代邮件/微信发 Excel 和图稿 |
| **全流程可追踪** | 订单状态实时可见，从下单、生产、发货到签收全程留痕 |
| **数据闭环** | EPC/TID 数据从生产环节直接进入系统，品牌内全局唯一性校验（红线），打通数据断层 |
| **供应商弹性** | 系统化品控降低引入小厂的风险，提升产能弹性和议价能力 |

### 1.4 目标用户

| 用户 | 角色描述 | 核心诉求 |
|------|----------|----------|
| 品牌方采购员 | 负责提交标签订单 | 快速下单、按 SKU 填数量、查看订单进度 |
| 品牌方打单员 | 负责创建和维护标签模板 | 维护模板字段、即时创建模板、处理补单 |
| 品牌方财务 | 负责对账付款 | 查看对账单、导出 Excel、下载发票 |
| 平台运营人员 | 审核订单、分配生产任务 | 审核订单信息、拆单转单、处理异常 |
| 供应商接单员 | 接单并进行生产 | 预览图稿、核对信息、确认接单 |
| 供应商生产员 | 上传生产数据 | 上传 EPC/TID 数据、查看校验结果 |
| 供应商发货员 | 负责发货 | 填写发货信息、打印送货单和包装贴 |

### 1.5 成功指标（MVP）

- 品牌方可独立完成下单（两种路径均可用），无需线下沟通
- 平台方可完成拆单转单，供应商 1 小时内收到通知
- 供应商可在线预览图稿并确认接单
- EPC 数据上传后 30 秒内完成校验并返回结果
- 对账单可按客户和时间段自动生成并导出 Excel

## 二、目标用户画像

### 2.1 品牌方 — 采购员

- **场景**：成衣工厂需要标签时，采购员登录系统下单
- **使用频率**：每周 1-3 次集中下单
- **核心操作**：选择模板类型 → 查看自动匹配的模板 → 填写各 SKU 对应数量 → 提交订单
- **关注点**：下单速度、模板能否自动匹配、补单能否复用历史数据
- **痛点**：以前要翻邮件找上次的 Excel 模板，手工复制粘贴 SKU 和数量，容易漏填或填错

### 2.2 品牌方 — 打单员

- **场景**：采购提交了只有 SKU+数量的订单，打单员为这些 SKU 创建标签模板
- **使用频率**：新品牌接入时集中创建模板，日常偶有补单模板修改
- **核心操作**：查看待补模板订单 → 为每个 SKU 创建/选择模板 → 填写品名、执行标准、尺码、洗涤方式 → 确认推送
- **关注点**：模板字段灵活可配（不同品牌模板字段不同）、可复用已有模板
- **痛点**：以前用 Excel 维护模板，品牌多了模板版本混乱

### 2.3 品牌方 — 财务

- **场景**：定期核对标签账单，安排付款
- **使用频率**：每月 1 次对账
- **核心操作**：按时间段生成对账单 → 逐行核对 SKU/数量/单价/发货情况 → 确认 → 导出 Excel
- **关注点**：对账单数据准确、导出格式可直接用于财务系统
- **痛点**：以前对账单靠人工汇总各供应商的散单，费时且易遗漏

### 2.4 平台方 — 运营人员

- **场景**：审核品牌方订单，拆单分派给供应商，处理异常
- **使用频率**：每日持续处理
- **核心操作**：审核订单信息与图稿 → 大订单拆分为多个子订单 → 选择供应商并分配数量 → 发送通知
- **关注点**：新订单提醒及时、拆单操作高效、异常订单能快速定位
- **痛点**：以前靠微信/电话协调供应商，大订单拆分靠手工分配，容易分配不均

### 2.5 供应商 — 接单员

- **场景**：收到新订单通知后登录查看并确认接单
- **使用频率**：每日检查新订单
- **核心操作**：查看订单详情 → 在线预览图稿 → 核对品名/字号/打印位置 → 确认接单或反馈异常
- **关注点**：图稿清晰可缩放、核对信息一目了然
- **痛点**：以前图稿通过微信发，图片压缩模糊，信息确认靠来回沟通

### 2.6 供应商 — 生产员

- **场景**：生产完成后上传 EPC/TID/二维码数据
- **使用频率**：每批次生产完成后上传一次
- **核心操作**：上传 xlsx/csv 数据文件 → 查看校验结果 → 处理异常数据 → 确认生产完成
- **关注点**：校验速度快、异常定位准确（哪一行哪个字段有问题）
- **痛点**：以前无系统校验，重码错码到客户手里才发现，造成批量返工

### 2.7 供应商 — 发货员

- **场景**：打包发货并填写物流信息
- **使用频率**：每日发货时操作
- **核心操作**：填写发货数量 + 快递单号 → 打印送货单 → 下载包装贴 → 上传签收单
- **关注点**：分批发货操作方便、送货单自动关联订单、包装贴直接打印
- **痛点**：以前送货单手工填写，包装贴需要自己做小工具排版

### 3.1 实体层级与架构

系统采用三层实体架构，自上而下管理标签业务：

```
客户公司（某服装集团）
├── 品牌A（标签模板、EPC 规则 归属品牌级）
│   ├── 工厂1（下单主体，独立对账）
│   └── 工厂2
├── 品牌B
│   └── 工厂3
```

| 层级 | 实体 | 说明 |
|------|------|------|
| L1 | **客户公司** | 实际的业务客户主体。一个客户公司可运营多个品牌。 |
| L2 | **品牌** | 挂靠在客户公司下。模板、EPC 规则、下单均以品牌为维度。 |
| L3 | **工厂** | 挂靠在品牌下。独立下单，数据可汇总至品牌。 |

**品牌切换规则**：
- 平台方可配置客户公司的 `allow_brand_switch` 开关
- 开启：品牌方用户登录后可在顶栏切换当前操作品牌，切换后模板/订单/工厂等数据跟随品牌上下文
- 关闭：品牌方用户登录后锁定单一品牌，不显示切换控件

### 3.2 账号注册与添加

系统不开放公开注册，所有账号通过以下方式创建：

| 客户公司 | 平台运营后台添加 | 平台运营 | 运营录入客户公司信息（名称、联系人、手机/邮箱） + 配置 `allow_brand_switch` 开关 → 创建客户公司实体 |
| 品牌（隶属客户公司） | 平台运营后台添加 | 平台运营 | 运营选择客户公司 → 新增品牌 → 录入品牌信息 + 品牌管理员手机/邮箱 → 系统生成初始密码 → 短信/邮件通知品牌方 → 首次登录强制修改密码 |
| 成衣工厂子账号 | 品牌方管理员自行创建 | 品牌方管理员 | 品牌方在「工厂管理」页面新增 → 填写工厂名称 + 联系人 + 手机号 → 子账号激活 → 短信/邮件通知工厂 |
| 供应商账号 | 平台运营后台添加 | 平台运营 | 运营录入供应商信息 + 联系人手机/邮箱 → 系统生成初始密码 → 短信/邮件通知供应商 → 首次登录强制修改密码 |
| 内部运营账号 | 超级管理员后台添加 | 超级管理员 | 超管在后台创建运营人员账号 → 分配角色权限 → 首次登录强制修改密码 |

**规则**：
- 所有账号首次登录须强制修改初始密码
- 品牌方管理员停用后，其下所有工厂子账号同步停用
- 工厂子账号仅可查看本工厂创建的订单，不可跨工厂操作
- 客户公司停用后，其下所有品牌及工厂同步停用
- 品牌切换由平台方通过 `allow_brand_switch` 开关控制：开启后品牌方用户登录可在顶栏切换品牌，关闭则锁定单一品牌

## 四、品牌方下单模块

### 4.1 路径一：预维护模板下单（标准路径）

> **品牌上下文**：下单均在当前选定品牌下进行。若客户公司配置了 `allow_brand_switch = true`，用户可在顶栏品牌切换器中切换品牌后再下单。

**前置条件**：品牌方已在系统维护标签模板。

**操作流程**：

```
采购员登录 → 选择"模板下单" 
  → 选择标签类型（吊牌标签 / 不干胶贴纸标签 / 洗麦标签） 
  → 系统按品牌默认规则自动匹配模板 
  → 采购员查看模板内容，支持手动微调 
  → 填写各 SKU 对应需求数量（支持批量导入 Excel） 
  → 填写收货信息（收货地址、联系人、联系电话） 
  → 确认提交 
  → 系统生成订单号，状态 = 待审核
  → 推送通知至平台运营
```

**模板匹配规则**：
- 每个标签类型可设置一个默认模板
- 下单时自动填充默认模板
- 采购员可切换同类型其他模板

### 4.2 路径二：即时生成模板下单

**适用场景**：品牌方初次接入，未提前维护模板；或临时新增 SKU 无匹配模板。

**操作流程**：

```
采购员登录 → 选择"即时下单" 
  → 填写 SKU + 数量（支持多行录入或 Excel 导入）
  → 填写收货信息（收货地址、联系人、联系电话）
  → 提交 → 订单状态 = 待补模板
  → 系统通知品牌方打单员
  ─── 角色切换 ───
打单员登录 → 查看待补模板订单 
  → 为每个 SKU 创建模板（填写：品名、执行标准、尺码、洗涤方式 等）
  → 或从已有模板库选择并关联
  → 确认 → 订单状态 = 待审核
  → 推送通知至平台运营
```

### 4.3 补单规则

| 规则 | 说明 |
|------|------|
| 模板匹配 | 同 SKU 补单时，系统自动匹配该 SKU 最近一次使用的模板 |
| 允许修改 | 匹配后可手动修改模板内容后提交 |
| 无需重建 | 不要求重新创建模板，减少重复操作 |
| 历史追溯 | 补单记录关联原订单，可查看补单历史 |

### 4.4 订单数据校验

- SKU 不能为空
- 数量必须 > 0
- 模板必须包含所有必填字段且已填写
- 路径二订单在模板未补全前，不可推送到平台审核

## 五、平台方接单转单模块

### 5.1 订单审核

**审核通过**：
```
运营登录 → 待审核订单列表 → 点击审核 
  → 查看订单信息（品牌方、工厂、SKU、数量、模板内容、图稿、收货信息） 
  → 确认无误 → 点击"审核通过" 
  → 订单状态 = 已审核
```

**审核驳回**：
```
信息有误 / 图稿不符 → 点击"驳回" 
  → 填写驳回原因（必填） 
  → 订单状态 = 已驳回 
  → 通知品牌方修改后重新提交
```

### 5.2 拆单转单

**操作流程**：
```
已审核订单 → 点击"拆单转单" 
  → 选择供应商（多选） 
  → 为每个供应商分配生产数量（支持百分比或手动输入） 
  → 系统校验：各供应商数量之和 = 订单总数量 
  → 确认拆分 → 生成多个子订单 
  → 每个供应商收到邮件通知（含订单基本信息） 
  → 子订单状态 = 待接单
```

**拆单示例**：
```
父订单：品牌A · 吊牌标签 · SKU-001 · 200万张

拆分结果：
  子订单-1 → 供应商甲 → 40万张 → 订单号 TH20260605-1
  子订单-2 → 供应商乙 → 40万张 → 订单号 TH20260605-2
  子订单-3 → 供应商丙 → 40万张 → 订单号 TH20260605-3
  子订单-4 → 供应商丁 → 40万张 → 订单号 TH20260605-4
  子订单-5 → 供应商戊 → 40万张 → 订单号 TH20260605-5
```

**校验规则**：
- 至少选择 1 个供应商
- 各供应商分配数量之和必须等于父订单总数量
- 不拆分时等同于全量分配给 1 个供应商

### 5.3 通知机制

| 触发节点 | 通知对象 | 通知方式 |
|----------|----------|----------|
| 品牌方提交订单 | 平台运营 | 邮件 |
| 审核通过 | 品牌方 | 邮件 |
| 审核驳回 | 品牌方 | 邮件 |
| 拆单转单 | 各供应商 | 邮件 |

## 六、供应商生产模块

### 6.1 接单对稿

```
供应商登录 → 待接单订单列表 → 点击订单详情 
  → 查看订单基本信息 
  → 在线预览图稿（支持缩放、拖拽） 
  → 核对信息清单：
      ☐ 品名正确
      ☐ 字号符合要求
      ☐ 打印位置正确
      ☐ 其他备注要求
  → 全部确认 → 点击"确认接单" → 状态 = 已接单 → 生产中
  → 有异常 → 点击"反馈异常" → 填写异常描述 + 上传附件 → 状态 = 异常待处理
```

### 6.2 EPC 数据上传与校验

**上传**：
```
生产完成 → 进入 EPC 数据上传页面 
  → 拖拽或选择 xlsx/csv 文件 
  → 系统解析文件，提取 EPC / TID / 二维码列 
  → 数据存入临时表，触发校验
```

**校验规则**：

| 校验类型 | 规则 | 异常处理 |
|----------|------|----------|
| 重码校验（红线） | 同一品牌内 EPC 全局唯一，不可与历史生产数据及当前其他子订单重复 | 标记重复行，列出重复 EPC 值及冲突来源（历史数据/其他订单） |
| 格式校验 | EPC 长度/前缀/字符集符合品牌规则 | 标记异常行，说明不匹配的规则 |
| SGTIN-96 校验 | 公司前缀 + 商品参考 + 序列号 三部分均合法 | 标记异常行，指出哪部分不合法 |
| 流水号校验 | 符合前缀 + 起始序号 + 递增规则 | 标记异常行 |
| 数量校验 | 上传数据行数 = 订单数量 | 不一致时提示差异 |

**校验结果返回**：
```json
{
  "passed": 199850,
  "failed": 150,
  "total": 200000,
  "errors": [
    {"row": 1234, "epc": "xxx", "reason": "EPC 重复：与历史生产数据冲突"},
    {"row": 5678, "epc": "yyy", "reason": "格式不匹配：公司前缀应为 3034"}
  ]
}
```

### 6.3 生产状态流转

```
待接单 → 已接单 → 生产中 → 生产完成 → 可发货
              ↘ 异常待处理 → （运营处理后）→ 生产中
```

## 七、发货物流模块

### 7.1 分批发货

```
供应商进入订单详情 → 点击"发货" 
  → 填写：
      · 本次发货数量（≤ 待发数量）
      · 快递公司（下拉选择）
      · 快递单号
  → 系统自动生成批次流水号（SH + 日期 + 序号） 
  → 提交 → 创建发货记录 
  → 累计已发 = 订单总数 → 订单状态 = 已发货
  → 累计已发 < 订单总数 → 订单状态 = 部分发货
```

### 7.2 签收方案

| 方案 | 触发条件 | 操作 |
|------|----------|------|
| **电子回单** | 品牌方要求签收 | 供应商上传电子签收单（图片/PDF）→ 品牌方确认 → 标记已签收 |
| **默认自动收货** | 品牌方未要求签收 | 发货后 N 天（可配置）→ 系统自动标记已签收 |

### 7.3 送货单

```
供应商在订单详情页 → 点击"生成送货单" 
  → 系统根据订单信息生成标准化送货单 
  → 送货单包含：订单号、SKU、数量、发货数量、快递单号、日期 
  → 支持下载 PDF / 直接打印
```

### 7.4 包装贴

| 类型 | 内容 | 使用场景 |
|------|------|----------|
| 小包贴 | SKU、款号、颜色、尺码、数量 | 每个小包装袋 |
| 中包贴 | SKU、款号、总数 | 多个小包集合 |
| 箱贴 | SKU、款号、总数量、箱号 | 外箱标识 |

模板由平台方预设，供应商在线下载后直接打印不干胶贴。

## 八、对账回款模块

### 8.1 对账单生成（品牌方方向）

**生成规则**：
- 按工厂、品牌、或客户公司三个维度（详见 8.4）+ 时间段汇总
- 汇总范围：该时间段内 **已签收** 的所有子订单
- 自动计算金额 = Σ（数量 × 单价）

**对账单内容**：
| 字段 | 来源 |
|------|------|
| SKU | 子订单信息 |
| 数量 | 子订单数量 |
| 单价 | 系统配置的标签单价（按 SKU/类型） |
| 金额 | 数量 × 单价 |
| 发货时间 | 发货记录 |
| 快递单号 | 发货记录 |

**导出**：Excel 格式（.xlsx），含表头样式和金额格式。

### 8.2 发票与账期

```
对账单确认 → 平台方上传发票（关联对账单）→ 品牌方可在系统查看/下载 
  → 系统按约定账期（如 30 天）计算到期日 
  → 每日检查超期未付账单 
  → 超期 → 标记预警 + 通知品牌方 
  → 超期且未付 → 品牌方新订单创建时拦截，提示先结清
```

### 8.3 供应商对账（镜像逻辑）

- 供应商维度汇总已签收子订单
- 供应商生成对账单 → 上传发票
- 平台方确认对账单 → 安排付款
- 平台方标记付款状态（已付款 / 未付款）
- 逻辑与品牌方方向一致，方向相反

### 8.4 对账单聚合维度

对账单支持三个维度的聚合，用户可按需选择：

| 维度 | 汇总范围 | 使用场景 |
|------|----------|----------|
| **按工厂** | 单个工厂下所有已签收子订单 | 工厂独立核算，基础粒度 |
| **按品牌** | 同一品牌下所有工厂的已签收子订单汇总 | 品牌整体对账，多工厂统一结算 |
| **按客户公司** | 客户公司下所有品牌的已签收子订单汇总 | 集团级对账，跨品牌统一结算 |

系统默认按工厂维度生成对账单，品牌方可在对账页面切换聚合维度。各维度对账单均支持导出 Excel。

## 九、逆向流程

### 9.1 订单取消

**标准规则**：
- 仅允许在订单未进入生产环节前取消（状态 ≤ 已接单）
- 取消后所有子订单状态 = 已取消

**特殊规则**：
- 配置 `allow_cancel_after_production = true` 的品牌
- 任意节点均可取消
- 已生产标签由商家另行处置，不计入对账单

**取消操作**：
```
品牌方进入订单详情 → 点击"取消订单" 
  → 二次确认弹窗 → 选择/填写取消原因 
  → 系统校验当前状态是否允许取消 
  → 允许 → 所有子订单批量变更为已取消 
  → 通知平台运营和已分配供应商
```

### 9.2 砍单

**规则**：
- 仅减少数量，不取消整单
- 已生产部分不可减少（保护供应商已投入成本）
- 仅减少未生产部分的子订单数量
- 已生产部分的费用由品牌方承担，纳入对账单

**砍单操作**：
```
品牌方进入订单详情 → 点击"砍单" 
  → 输入新的目标数量 
  → 系统校验：新数量 ≥ 已生产数量（否则拦截） 
  → 减少数量 = 原数量 - 新数量 
  → 从未生产子订单中扣除 
  → 订单状态 = 已砍单（不影响已生产子订单继续流转）
```

### 9.3 免费单

- **品牌方不暴露免费单选项**：品牌方下单时仅可选择「大货单」或「补单」，防止客户滥用免费单
- **由平台方标识**：平台运营人员在接单/审核环节可将订单标记为「免费单」，标识后订单金额 = 0
- 免费单走完整下单流程，不跳过任何订单流转环节
- 生成对账单时，免费单金额列 = 0

## 十、EPC 编码规则

### 10.1 SGTIN-96 可解析编码

**适用场景**：新货期货订单，需要 EPC 能反解析出 SKU 信息。

**编码结构**（96 位）：
```
| 标头(8) | 滤值(3) | 分区(3) | 公司前缀(20-40) | 商品参考(24-4) | 序列号(38) |
```

**配置项**：

| 参数 | 说明 | 示例 |
|------|------|------|
| 公司前缀 | GS1 分配的企业前缀 | 3034、3035 |
| 商品参考 | 企业内商品编码，映射到 SKU | 对应 SKU 的编码 |
| 序列号范围 | 起始和结束序列号 | 000000001 - 999999999 |
| 滤值 | 包装层级标识 | 0-7 |

**生成规则**：
- 根据 SKU 反查商品参考编码
- 序列号从起始值递增
- 生成后不可重复

### 10.2 自定义流水号编码

**适用场景**：存量标签补货，不需要反解析，只需唯一标识。

**编码格式**：`前缀 + 流水号`

**配置项**：

| 参数 | 说明 | 示例 |
|------|------|------|
| 前缀 | 品牌自定义字母前缀 | A、B、C |
| 起始序号 | 流水号起始值 | 001 |
| 递增步长 | 每次递增的值 | 1 |
| 补齐位数 | 流水号固定位数（前补零） | 3 位 → A001 |

**生成规则**：
- 原子递增（防止并发重复）
- 取当前值后立即 +1
- 生成速度比 SGTIN-96 快

### 10.3 双规则共存

- 同一品牌方可同时配置两种规则
- 下新货订单时使用 SGTIN-96 规则
- 补货订单时使用流水号规则
- 系统根据订单类型自动选择匹配的规则
